Featured System

MuSHR478: Autonomous Driving on the MuSHR Platform

This project builds a full autonomous driving stack for an Ackermann-steered MuSHR car. It integrates localization, planning, and control into one closed-loop navigation system that can execute real autonomous driving behavior on a mapped environment.

Open Source README

Core Scope

  • Particle-filter localization on a known map
  • Roadmap planning with Dubins feasibility and Lazy A*
  • Path tracking with PID, Pure Pursuit, and MPC
  • End-to-end system integration for closed-loop navigation

Problem Statement

Driving a car-like robot is a coupled system problem

The MuSHR platform uses Ackermann steering, so it cannot move sideways or rotate in place like a differential-drive robot. That changes the entire autonomy stack: localization must estimate heading accurately, planning must respect curvature constraints, and control must track feasible vehicle motion under noisy sensing and delayed execution.

Architecture

Localization, planning, and control operate as one loop

Sensors -> Localization -> Planner -> Controller -> Vehicle -> Sensors

The stack answers three questions repeatedly: where the vehicle is, what path it should follow, and what steering plus speed command it should execute right now.

Main Components

Detailed breakdown

Localization

Pose estimation is handled with a particle filter that repeats motion prediction, LiDAR-based sensor likelihood update, weight normalization, and low-variance resampling.

Planning

Planning happens in state space `(x, y, theta)`. A roadmap is sampled in free space, connected with Dubins-feasible edges, searched by Lazy A*, and then shortened by path shortcutting.

Control

Three controllers were implemented and compared: PID as a baseline, Pure Pursuit for geometric path tracking, and MPC for predictive control with stronger future reasoning.

Integration

The project emphasizes ROS communication, TF consistency, planner-controller compatibility, and parameter tuning that works in real closed-loop execution rather than only in isolated tests.

Engineering Takeaways

Why this project matters

  1. It demonstrates system-level autonomy rather than disconnected robotics assignments.
  2. It shows comfort working across estimation, planning, control, and execution feedback loops.
  3. It reflects practical debugging of real-time constraints, state drift, and path trackability.
